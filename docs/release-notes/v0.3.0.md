# SubtitleFlow v0.3.0

## 字幕处理

- **清理字幕**：新的处理方式。去掉解码失败留下的 � 和不可见控制字符，删除语音识别“幻听”产生的乱码条目（一句里混进与整份字幕无关的文字，例如泰语字幕夹着韩文、俄文），输出清理后的 SRT 和逐条列出改动的清理报告，可回到原字幕核对。不需要翻译服务。
- **看得到翻译进度**：每个文件的进度格显示已译条数和进度条，进行中蓝色、重试琥珀色、失败红色、完成绿色；底部总进度按文件内的完成比例计算。点文件名前的 ▸ 展开详情卡片：当前批次、这一批从哪个时间点开始和原文、请求已等待多少秒、重试原因、保留原文的条目。
- **长字幕不再因个别条目整份失败**：
  - 一批译文条数对不上、输出被截断或超时，会对半拆开重试；单条仍翻不出来就保留原文，并在详情卡片里列出。超过全文 5% 时仍判失败，并提示检查模型或先清理字幕。
  - 同一字符连续很多次（如“ยยยย…”）时缩短后再发给模型，并限制每次回复长度，模型复读能很快收场。
  - 能从推理模型带思考过程的回复里正确取出译文。
- **请求超时**：本机模型默认等待 300 秒，云端 API 60 秒，可在「翻译设置 → 请求超时」中调整。超时只再重试一次，随后拆小批次。
- **排查日志**：每个任务目录新增 `translate.log`，记录每批的耗时、重试和原因，不含字幕正文和密钥。响应超时不再被误报成“API 响应不是兼容的聊天结果”。
